# 第二部分　两条路线

## 03　流式启动与无闪存启动不是一回事

![Streaming Boot vs Flash-less Boot：左侧流式启动（BMC/Host 流式传输 → RoT/FPGA → 载入 SRAM → 执行），右侧无闪存启动（ROM → 分块接收 → 验证 → 存入 SRAM → 执行）](images/03_04m22s.jpg)

那我们再深入一点，讲这两种方式的差异。左边是流式启动。流式启动本质上是通过网络流把固件提供给节点——你有基础设施层，所有固件都存放在那里；然后系统自己从一段不可变的 ROM 启动。系统会知道——比如说 BMC 或 FPGA 会知道——去哪里取数据，然后开始抓取数据、把数据加载到系统的 SRAM 里。之后这些数据可以被转换，并以某种状态呈现给 CPU。所以在这个流式传输的部分，系统上完全不需要有闪存器件，只需要知道从哪里拿到镜像、从哪里拿到设备的固件。右边是无闪存启动，它很相似，但主要区别在于：无闪存启动里我们在系统上保留一小部分，用来放一段"早期固件启动"，由它告诉系统去哪里找其余的固件。早期固件只有很少的指令，说明从哪里取东西；其余的固件才包含真正的 BIOS 和可执行文件等等。

![Architectural Distinctions of Two Complementary Approaches：控制点、验证粒度、传输依赖、互补性四行对照](images/04_06m20s.jpg)

## 07　早期固件与次级固件：真正的难点

![Early FW vs. Secondary FW: The Streaming Challenge：阶段、大小、DRAM 可用性、流式模型、验证方式、失败影响六行对照](images/07_13m20s.jpg)

……也就是说，在高层面上……我们做了一些实验，就像 Alex 展示的那些时序，因为这是重要的部分。但整件事最难的地方在于：无论你选哪种机制，都必须有一段早期固件和一段次级固件，并且要让它们以某种方式协同工作。我说的早期固件是指：一个空白的 CPU 没有任何办法去下载大容量的东西。早期固件的概念就是让 CPU 准备好，从 DMI 或其他阶段接收镜像——那些阶段可以处理巨量数据。所以理想情况下早期固件应该非常小，你要让它尽可能简单、尽可能小。它应该包含 DMI 训练时序以及所有必须在那里完成的事情。另外还有一个附加条件：你可能希望在那里放一份安全检查清单，因为一旦你验证了早期固件，早期固件就可以去验证次级固件——如果你选择这种方式的话。这是另一个可以做的附加项。所以拥有早期固件大概是最难的部分，因为早期固件有非常非常紧的时间约束，你必须确保它在特定时间内响应，这是 CPU 的要求。如果你看左边，我们建议早期固件应该小于——我记得他们给出的数字，我看到 CPSS 大约是 6 MB，但我们看到的情况是接近 4 MB。而且早期固件也需要某种验证，因为你是把早期固件当作次级固件的安全基础。次级固件基本上是：当 DMI 训练完成，CPU 可以从 DMI 的角度放入镜像，那在次级固件阶段会快得多，然后你也可以在那里做某种安全检查。所以早期固件最大的挑战是：在早期阶段几乎没有延迟容忍度，因为 CPU 会立即开始取数据，你在取数过程中看到的任何延迟都可能让 CPU 挂起、根本无法启动——这是一个非常关键的阶段，因为 CPU 就是这样工作的。我们用 Intel CPU 做过一些实验，这是我们发现的。现在我不认为有——有一些实验性的方式可以让 PC 工作，但我不认为目前有任何生产级的工作完成。另外早期固件没有 DMI 缓冲，所以我认为我们唯一的选择是用 APGS RAM 来存放这 4 MB 数据作为早期固件。我们试图解决的关键问题之一是：由于复位、由于这类信号的时序要求，你希望早期固件是一份非常顺序化的镜像。所以这不只是固件的问题，eSPI 通道上还有别的信号来回走。这必须是高度可预测的，而今天它并不可预测，这是我们仍然面对的挑战之一。我不是说它顺序化，我是说这是另一个我们面对的挑战。我想这里有三条信息——我知道我时间不多了，但我要展示三条信息，说明早期固件可以待在哪里。在很高的层面上，我们可以让早期固件待在 BMC 里……抱歉，好，谢谢。这里有三个匹配项：你可以让 BMC 的 SPI 闪存保存固件，次级可以放在 PCH 闪存里保存早期固件；你也可以把所有东西都放进 PCH；或者如果你想要不止一份固件镜像——如果你有分区系统之类的东西——你可以增加只与 PCH 通信的额外 eMMC……

## 09　结论：部署发生在需要的地方
